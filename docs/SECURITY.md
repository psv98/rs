# Безпека

Загрози, з яких виходили: підміна або видалення статистики, захоплення адмін-панелі, публікація незавершених даних, XSS через тексти, DoS через важкий PNG-рендер.

| # | Вимога | Реалізація |
|---|---|---|
| 1 | Авторизація на сервері для кожної адмін-операції | `adminRoute()` у `src/lib/auth/guard.ts` для кожного API; `requireAdminPage()` для кожної сторінки. `proxy.ts` лише перенаправляє, захистом не є |
| 2 | Argon2id | `@node-rs/argon2`: m = 64 МіБ, t = 3, p = 1 |
| 3 | Перебір паролів | 5 невдалих спроб на ім'я → блокування на 15 хв (подвоюється, до 24 год); 20 з IP → 30 хв. Стан зберігається в БД. Однаковий час відповіді й однакове повідомлення для неіснуючого користувача |
| 4 | Cookie | `__Host-imi_admin`: HttpOnly, Secure, SameSite=Strict, Path=/. Токен 256 біт; у БД — лише SHA-256. Таймаути: 2 год бездіяльності, 12 год абсолютний |
| 5 | CSRF | SameSite=Strict + перевірка Origin + обовʼязковий `application/json` + токен сесії в заголовку `X-CSRF-Token` |
| 6 | Валідація | Zod для кожного тіла запиту, ліміт розміру тіла |
| 7 | XSS | React екранує текст; у текстах заборонені `<…>`, `javascript:`, обробники подій і керівні символи; посилання лише https. CSP з nonce і `strict-dynamic` |
| 8 | SQL-ін'єкції | лише параметризовані запити Kysely |
| 9 | Публічна зміна даних | публічні маршрути лише читають опубліковані знімки |
| 10–11 | Секрети | секретів у клієнтському коді немає; `.env` і БД виключені з Git; пароль адміністратора вводиться в CLI і зберігається лише як хеш |
| 12 | Права БД | PostgreSQL: власник міграцій окремо; роль застосунку без `DROP` і без `DELETE` на `audit_log` (перевірено) |
| 13 | Навантаження експорту | token bucket на IP, не більше 2 одночасних рендерів і черга до 20, кеш за контрольною сумою, ETag |
| 14 | HTTP-заголовки | CSP (nonce), HSTS, X-Content-Type-Options, Referrer-Policy, X-Frame-Options, COOP, CORP, Permissions-Policy; `noindex` і `no-store` для адмінки |
| 15 | Залежності | `npm audit` у CI, Dependabot, мінімум залежностей |
| 16 | Журнал змін | `audit_log`: входи (успішні й ні), збереження, публікації, відкати, імпорт/експорт |
| 17–18 | Копії та відкат | автоматична JSON-копія після кожної зміни публікації; «Відновити версію», «Зняти з публікації», `db:restore` |
| 19 | SVG | іконки перевіряються за білим списком елементів/атрибутів під час збірки; завантаження SVG через форми немає |
| 20 | Розкриття помилок | API повертає код інциденту без деталей; деталі лише в серверному журналі |

Додатково:

- опубліковані знімки незмінні, виправлення створює нову версію;
- контрольна сума кожного знімка; пошкоджена публікація не показується;
- для публікації, зняття й відновлення треба ввести дату знімка, для зняття й відновлення — ще й причину.

Рекомендації для продакшну: HTTPS через reverse proxy з `TRUST_PROXY=1`; обмеження частоти запитів на рівні проксі/CDN; доступ до `/admin` за IP або VPN, якщо це можливо; щоденні копії БД поза сервером; регулярне оновлення залежностей.
