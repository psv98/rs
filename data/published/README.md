# Опубліковані дані для GitHub Pages

`snapshots.json` — те, що показує статичний сайт на GitHub Pages. Кожен push у `main` запускає перебудову сайту.

Як опублікувати знімок, який уже лежить у файлі: у блоці `verification` поставте `"sourceChecked": true` (цифри звірено з публікацією ІМІ) і `"sumMismatchConfirmed": true` (розбіжність суми категорій підтверджено, пояснення UA/EN заповнене). Ці два прапорці ставить лише редактор.

Як оновити:

1. **Через адмін-панель (рекомендовано).** Опублікуйте знімок у локальній адмінці, потім `npm run pages:export` або «Резервні копії → Завантажити snapshots.json», замініть файл і зробіть commit.
2. **Прямо на GitHub.** Відредагуйте файл у вебінтерфейсі GitHub і збережіть.

Перед публікацією збірка перевіряє файл за тими самими правилами, що й адмінка: переклади, дати, звірка з джерелом, підтвердження й пояснення розбіжності суми категорій. Знімок, який не проходить перевірку (наприклад, редактор ще не підтвердив звірку), на сайт не потрапляє, а в журналі GitHub Actions зʼявляється попередження з переліком причин. Якщо файл зламаний синтаксично, збірка зупиняється й на сайті лишається попередня версія.

Доступ до змін = доступ на запис до репозиторію. Рекомендовано увімкнути захист гілки `main` і двофакторну автентифікацію для всіх, хто має запис.
